## Scope and design choices

- Regular: alpha 0.62, blur 12px, saturation 180%. Clear: alpha 0.35, blur 6px, saturation 140%. Frost: alpha 0.78, blur 20px, saturation 200%. The plan specifies recipes but not Clear/Frost opacity; these alpha values are implementation choices. Manual transparency reduces blur proportionally below the preset alpha, capped at the preset blur above it.
- Preserve neutral light/dark colors by default. Add cool white, warm gray, and ink tints, each with explicit light/dark values. Tints do not alter text or accent tokens.
- New backdrop-filter CSS targets only `[data-liquid-glass-preview]::before`, a childless, noninteractive decoration. Its containing block cannot capture a host fixed-position descendant. New host frosting is limited to the existing menu-material token consumers. The old blanket `body > *` background reset and body background override are removed.
- A 1px border and inset top highlight are provided on the plugin's material preview only. The host settings-card rim uses its official stroke token. Native menu fills have an alpha floor of 0.55; this is **not** a user/assistant-message opacity floor.
- Wallpaper: cover/contain/fill, all nine positions, brightness 20–200%, manual black dim 0–60%. Image brightness and dim use separate plugin-owned fixed layers with explicit stacking order; neither is a host container. All new visual preferences persist in one validated `dsh-liquid-glass:options` JSON record. The old alpha key and its rounding/clamp remain unchanged. Preset saves restore the old alpha if saving the options fails and show an inline failure.
- Auto dim defaults on. A 16×16 sample computes alpha-weighted average RGB luma. After multiplying by the brightness setting, values above 0.70 trigger a **minimum** 35% black dim: `max(manualDim, 35)`, not additive dim. The threshold, combination rule, and single-frame sampling are implementation choices because the plan does not define them. GIF bytes remain untouched; auto dim samples one decoded frame, not an animation-wide brightness guarantee.
- Cross-origin URLs skip sampling. Same-origin URLs and image data URLs may be sampled; decode failure, missing canvas support, or a tainted canvas fall back to manual dim. Revision checks discard late results after replacement or teardown.
- Either reduced transparency or increased contrast activates an effective Frost preset and alpha at least 0.5. It never makes an already more opaque choice more transparent. The UI caps transparency at 50% and disables preset changes during protection. Stored appearance preferences are preserved and restored when both preferences clear; the user's filter-off choice is respected. Unsupported media queries simply never match.
- “Toggle Liquid Glass” is editable/removable in the host's existing Keyboard shortcuts settings. The resolver additionally passes through editable/terminal input and modal contexts, including on desktop where the host dispatcher otherwise prioritizes shortcuts.

## Deliberately omitted or unverified

1. **Separate user/assistant opacity floors and switches:** no verified official per-side background token or additive surface-decorator API. The user content factory is explicitly *not* a global user-content override (`dsh-client-ui-chat/README.md:48–52`); assistant Markdown has no exposed independent background token in `src/client/chat/AssistantMarkdown.module.css`. Replacing native message renderers, guessing DOM selectors, or changing the shared base token would not implement the requested independent floors safely. This P0 item is omitted.
2. **Arbitrary host card/panel blur and inset highlights:** no verified official hook for attaching a decoration to every such surface. Menu material tokens and settings-card stroke are supported, but `--dsw-elevation-panel` and related derived shadows are redeclared on every element (`dsh-client-ui-theme/src/styles/gradient-shadow-text.css:27–39`), so overriding them on the body's theme layer would not add a reliable highlight. Broad selectors or fake tokens are not used. This part of P0/P1 remains omitted.
3. **Linux Web Mod+Shift+G:** rejected by the official shortcut policy, so no default is registered for this profile. Host settings may assign an allowed, nonconflicting combination. Actual OS/browser delivery on supported profiles has not been tested.
4. **Actual DSH regression:** the smoke suite is mocked and does not prove real settings dialogs, popovers, menus, GIF playback, system preference delivery, screenshots, or low-end scrolling performance. A Chromium fixture was attempted with the already installed local browser; launch failed before executing the fixture with `setsockopt: Operation not permitted` (SIGTRAP) under the sandbox. No browser download, host modification, or sandbox escalation was attempted. Live-host validation remains outstanding.

## Instruction and plan discrepancies

- The plan still labels itself “research/plan only” and includes P3 in the v0.2.0 table while recommending v0.3.0. The explicit task supersedes that: implement P0–P2 only; no P3, desktop transparency, or WebGL refraction.
- The plan suggests a new keydown listener. A verified official shortcut registry exists, so the owner's official-API-only rule requires using it instead.
- The plan's universal Ctrl/Cmd+Shift+G suggestion is incompatible with Linux Web's official restrictions.
- The plan says all settings use localStorage. Plugin-owned visual preferences do. Official shortcut overrides use localStorage on Web but the host's device-local `keybindings.json` on Desktop (`dsh-client-shortcuts/README.md`). The official-API-only rule takes precedence over duplicating or bypassing host shortcut persistence.
- The supplied `VERDICT.md` and compatibility `REPORT.md` concern **dsh-archived-chats**, not this theme. They are not proof of this theme's live-host compatibility. The package manifest and approved compatibility decisions were left untouched.
- The original English slider label was “Opacity” while its value and behavior are transparency. The new UI corrects the label to “Transparency” without changing the approved alpha calculations.
